Here is the audit of the WP2 pipeline against the design and Ryan's rules.

### Findings

**1. [HIGH] Translation silently drops malformed predicates (Criterion 1 & 4)**
* `sv3/translate.py:normalise`
* **Defect:** When the translator invents a field for a predicate (e.g., putting `count` on `moving`, or using `for_s` instead of `for_s_before`), `normalise()` pops the invalid field from the dictionary and merely prints a warning to `sys.stderr`. It does not flag the translation as invalid or append to a `problems` list, so `local_check` passes and the pipeline proceeds with the requirement silently dropped.
* **Fix:** Pass a `problems` list into `normalise` and append to it when fields are dropped so `local_check` will fail the translation:
  ```python
  def normalise(shots, problems):
      for s in shots:
          for p in s["find"]:
              # ...
              for k in extra:
                  problems.append("%s %s(): dropped invalid field %s=%r" % (s["id"], p["p"], k, p.pop(k)))
      return shots
  ```

**2. [HIGH] Montage beat events miss their target words (Criterion 2)**
* `sv3/search.py:search_montage`
* **Defect:** When finding clips for a montage, `search_montage` calls `search_shot` in a loop but fails to pass `prev_len`. As a result, if the montage has a `beat` word, every single part calculates its anchor time (`tin = ta - (tw - prev_len)`) as if it starts at `0.0` in the final cut. When the parts are later concatenated by ffmpeg, part 2's event will miss its beat word by exactly the length of part 1. 
* **Fix:** Keep a running total of the montage length and pass it to `search_shot`:
  ```python
  prev_len = 0.0
  for _ in range(n):
      hit, miss = search_shot(recs, shot, words, pad, exclude_victims=used, prev_len=prev_len)
      # ...
      prev_len += hit["len"]
  ```

**3. [HIGH] Montages are held/frozen on screen long past the voice line (Criterion 3)**
* `sv3/search.py:search_montage`
* **Defect:** `search_shot` always computes `need = slot` because it reads the full voice line's length directly from `slot_of()`. When `search_montage` calls it, every single part of the montage is forced to find a window of the FULL line length. If the montage has a beat, `part = max(part, hit["len"])` forces every part to physically be `>= slot` long. A 3-part montage becomes `3 × slot` seconds long; `edl.py` sees `total > slot`, sets `fit="wait"`, and the final video is frozen/held on the montage long after the voice has ended (violating Rule 356).
* **Fix:** Modify `search_shot` to accept an `override_slot` argument, and have `search_montage` pass the fractional part length down:
  ```python
  def search_shot(recs, shot, words, pad, same_tape=None, prev_len=0.0, exclude_victims=(), override_slot=None):
      slot = override_slot if override_slot is not None else slot_of(shot, words, pad)
  ```
  *(and in `search_montage`, pass `override_slot=part`)*

**4. [HIGH] Old footage is reused even when Ryan orders "from scratch" (Criterion 5)**
* `sv3/search.py:run`
* **Defect:** Rule 417 explicitly states "start from scratch means no reused clip". While `plan.py` obeys `--from-scratch` by planning new captures, `search.py` completely ignores the `plan` parameter and searches the entire historical tape pool. If an older take in the pool happens to score better than the newly captured take, `search.py` will reuse the old footage, directly violating Ryan's order.
* **Fix:** Filter the candidate pool to only include tapes specifically ordered or generated by the plan's seeds:
  ```python
  def run(plan, shots, ...):
      recs = P.load_pool(pool)
      if plan and plan.get("matches"):
          allowed_tapes = {m["reuse_tape"] for m in plan["matches"] if m.get("reuse")}
          allowed_seeds = {m["seed"] for m in plan["matches"]}
          recs = [r for r in recs if r.tape in allowed_tapes or r.take.get("seed") in allowed_seeds]
  ```

**5. [MED] Plan merges intent strings, silently applying scripts to bodies that shouldn't have them (Criterion 5)**
* `sv3/plan.py:intents_arg`
* **Defect:** The design states "bodies not named keep their shipped brain." If Line 1 scripts `guard="miss:2"` (leaving runners to the bot brain) and Line 2 scripts `runner:1="run"` (leaving the guard to the bot brain), `intents_arg` merges them into `guard=miss:2;runner:1=run`. Line 1 is now filmed with a scripted runner instead of a bot, and Line 2 is filmed with a scripted guard instead of a bot. The plan's intent string silently disagrees with the requirements of both lines.
* **Fix:** Assert that every line belonging to the same match has the exact same `film.intents` dictionary, otherwise refuse the plan:
  ```python
  def intents_arg(group):
      first = (group[0].get("film") or {}).get("intents") or {}
      for s in group[1:]:
          if ((s.get("film") or {}).get("intents") or {}) != first:
              raise SystemExit("PLAN REFUSED: Lines sharing a match have conflicting film.intents")
      return ";".join("%s=%s" % (b, st) for b, st in first.items())
  ```

**6. [LOW] Regexes allow invented steps outside the vocabulary (Criterion 4 & 5)**
* `sv3/schema.py`
* **Defect:** The translator can invent `look:portal:2.0` because the regex allows `look:(tower|portal)`, even though the design doc restricts looking explicitly to `look:tower:<s>` alongside `portal` as a standalone trigger. Likewise, `GUARD_STEP` allows `wait:\d+`, which is outside the guard's closed vocabulary of `miss:N, hit, scope, idle`. `translate.py`'s `film_check` will let both pass silently.
* **Fix:** Restrict the regexes to the exact closed vocabularies:
  ```python
  RUNNER_STEP = r"^(run|cover:at:\d+(\.\d+)?|shove_when_rival_within:\d+(\.\d+)?|look:tower:\d+(\.\d+)?|portal|wait:\d+(\.\d+)?|brawl|idle)$"
  GUARD_STEP = r"^(miss:\d+|hit|scope|idle)$"
  ```

### What is Sound
* **Free Cameras:** Prevented successfully; `local_check` rejects match shots with a `free` camera.
* **Trailer Footage:** Kept out completely; `load_pool` enforces Rule 370 by skipping any tape with `"trailer"` in the name.
* **Synthesized Voice:** Banned successfully; the pipeline passes Ryan's text byte-for-byte to the table and never touches it. 
* **Player Counts:** Enforced safely by the `FILM` JSON Schema clamping `players` to a maximum of 4.
* **Beat Alignment:** Aside from montages, single clips trim their previous clips properly and hit their required lead time mathematically perfectly.
