1. REAL: `sv3/capture.py` (line 43) `run_clip_args` returns `m["run_clip_args"]` verbatim. Why it fails: A plan could maliciously or accidentally pass `--write-movie`, which forces Godot to render offline frames to disk while `pc_rough` simultaneously tries to capture the screen in real time, causing severe frame drops and violating the strict "no Movie Maker for rough takes" rule. Fix: Refuse the arg if it violates the rule: `if m.get("run_clip_args") and "--write-movie" not in m["run_clip_args"]: return m["run_clip_args"]`.
2. REAL: `lib.sh` (line 92) `pc_lock` renewer subshell `( while sleep 30; do pc ... done ) &`. Why it fails: If the Mac shell running the orchestrator or `assemble.sh` is forcefully terminated (e.g. `SIGKILL` or Python timeout), the `trap pc_unlock EXIT` is bypassed. The background subshell is orphaned, running forever on the Mac and permanently wedging the PC lock. Fix: Have the renewer loop exit if its parent dies, e.g., `while kill -0 $$ 2>/dev/null; do`.
3. REAL: `short3.sh` (line 12) `set -uo pipefail` missing `-e`. Why it fails: Setup commands like `mkdir -p "${WORK}/voice"` or `echo '{"steps": []}' > "${TIMING}"` will silently fail if they hit a disk or permissions error. The script will continue with missing folders or broken timing files, causing confusing downstream errors. Fix: Add `set -e` or append `|| die "failed"` to these lines.
4. BLOCKER: `short3.sh` (line 98) `step review sv3 review ...`. Why it fails: The design explicitly requires a review loop ("any `no` → that line's match re-searched with the next seed once, re-cut, re-reviewed"). The orchestrator runs the review exactly once and immediately halts on failure, completely missing the required retry mechanism. Fix: Wrap the `search`, `edl`, `assemble`, and `review` steps in a retry loop.
5. BLOCKER: `pc/assemble.py` (line 396) `avail_i = length if length is not None else max(dur(src) - s_in, 0.01)`. Why it fails: If a script uses `at=T len=L` and `L` is longer than the remaining actual clip duration, the input ends early. Because `fit_filter` applies `fps=60`, ffmpeg blindly duplicates the final frame to fill the remaining `-t` requested duration, freezing the video and violating the "nothing is ever frozen" rule. Fix: `avail_i = min(length, max(dur(src) - s_in, 0.01)) if length is not None else ...`
6. BLOCKER: `sv3/capture.py` (line 121) `subprocess.run(["scp", ...])`. Why it fails: `scp` is called with no `timeout` argument. If the SSH connection to the PC hangs during file transfer, the Python process will block indefinitely, completely blowing the strict 45-minute maximum time budget. Fix: Add `timeout=60` to the `subprocess.run` call for `scp`.
7. BLOCKER: `sv3/capture.py` (line 29) `seat_file(seat)` replacing `:` with `_`. Why it fails: The PC pool files are named with `_` (e.g., `runner_1.events.jsonl`) and are pulled to the Mac retaining that name. However, the design layout (§3) specifies `<seat>.events.jsonl` (e.g., `runner:1.events.jsonl`). WP2's search tool will look for the exact seat name and fail to find the logs, entirely breaking WP1/WP2 integration. Fix: When pulling files to the Mac, save them using the original `seat` string, which macOS allows (e.g., `os.path.join(mac_dir, f"{seat}.events.jsonl")`).
8. NIT: `short3.sh` (line 89) `step capture sv3 capture`. Why it fails: It lacks a preceding `need capture capture` check. If the WP3 module is missing, the script halts with a raw Python `ModuleNotFoundError` stack trace instead of stopping cleanly with the module name as the rules demand. Fix: Add `need capture capture` before the step.

Verdict: WP3 fundamentally delivers the integration but requires critical fixes for a broken retry loop, missing SCP timeouts, pool filename mismatches, and a clip-freezing bug.
